# יומן

יומן אישי מינימליסטי. PWA סטטי, בלי שרת ובלי בילד.
הרשומות יושבות ב-IndexedDB בדפדפן שלך. הגיבוי הולך לתיקייה בגוגל דרייב שלך.
אין צד שלישי בדרך.

```
index.html            שלד + עיצוב
config.js             ה-Client ID. הקובץ היחיד שצריך לגעת בו.
app.js                חיווט: מצב המסך, אירועים, עלייה
entries-store.js      הרשומות ב-IndexedDB
drive.js              חיבור לגוגל וקריאות דרייב
backup-file.js        פורמט קובץ הגיבוי
view.js               כל מה שנוגע ל-DOM
local-storage.js      אחסון מקומי שלא זורק
sw.js                 service worker — הדף עובד אופליין
manifest.webmanifest  התקנה כאפליקציה
icons/
```

מודולים נייטיב של הדפדפן (`type="module"`), בלי בילד ובלי תלויות.

## 1. Google Cloud

ה-scope היחיד הוא `drive.file` — האפליקציה רואה **רק קבצים שהיא עצמה יצרה**.
לא את שאר הדרייב שלך. זה scope לא-רגיש, ולכן **אין תהליך אימות אפליקציה**
ואין security assessment.

### להשתמש בפרויקט קיים או לפתוח חדש?

אפשר להשתמש בפרויקט קיים. מותר כמה OAuth Client IDs באותו פרויקט, וזה מקרה שימוש רגיל.
שלושה דברים לדעת לפני:

1. **מסך ההסכמה משותף לכל הפרויקט.** השם, הלוגו ולינק מדיניות הפרטיות מוגדרים
   פעם אחת ברמת הפרויקט. כלומר היומן יציג בהסכמה את השם של האפליקציה האחרת שלך.
   פונקציונלית זה לא משנה כלום; ויזואלית זה מוזר.
2. **הרשאות בזמן ריצה הן לפי בקשה, לא לפי פרויקט.** המשתמשים של האפליקציה השנייה
   לא יראו פתאום בקשת הרשאה לדרייב — כל client מבקש את ה-scopes שלו בלבד.
3. **אם הפרויקט הקיים כבר עבר אימות** — הוספת scope לרשימה המוצהרת עלולה לפתוח
   מחדש בדיקה. עם `drive.file` זה לא אמור לקרות כי הוא לא-רגיש, אבל אם האפליקציה
   האחרת שלך במצב Production ומאומתת, שווה פרויקט נפרד ולא לגעת בה.

לאפליקציה פרטית שרק אתה משתמש בה, פרויקט נפרד לוקח שתי דקות והוא נקי יותר.
זו ההמלצה, אבל שימוש חוזר יעבוד.

### הגדרה

1. ב-Google Cloud Console, בפרויקט הרלוונטי: **APIs & Services → Library → Google Drive API → Enable**
2. **OAuth consent screen**: User type `External`. מלא שם, אימייל תמיכה, פרטי מפתח.
3. ב-**Audience** הוסף את עצמך תחת *Test users*.
   מצב `Testing` מספיק לשימוש אישי — יש חריג אימות מפורש לשימוש אישי,
   ולזרימה בדפדפן אין refresh tokens בכלל (טוקן גישה חי כשעה ומתחדש בשקט),
   כך שתפוגת 7 הימים של Testing לא נוגעת לך.
4. **Credentials → Create credentials → OAuth client ID → Web application**.
   תחת *Authorized JavaScript origins* הוסף את המקור המדויק, בלי נתיב ובלי סלאש בסוף:
   ```
   https://liorhalfon.github.io
   http://localhost:8080
   ```
   *Authorized redirect URIs* — השאר ריק. הזרימה כאן היא token client, בלי redirect.
5. העתק את ה-Client ID ל-`config.js`:
   ```js
   export const GOOGLE_CLIENT_ID = "1234....apps.googleusercontent.com";
   ```

## 2. הרצה מקומית

service worker ו-OAuth דורשים origin אמיתי. `file://` לא יעבוד.

```bash
cd my-journal-app
python3 -m http.server 8080
```

ואז `http://localhost:8080` — localhost נחשב secure context, אז הכל עובד.

## 3. פריסה

כל אחסון סטטי. GitHub Pages, Netlify, Cloudflare Pages — העלה את התיקייה כמו שהיא.
תנאי אחד: **HTTPS**. בלעדיו אין service worker ואין OAuth.

שים לב ל-origin: ב-GitHub Pages כל הריפואים תחת אותו חשבון חולקים
`https://liorhalfon.github.io`, אז מקור אחד מכסה את כולם.

## גיבוי

בתיקייה `Journal Backups` בדרייב:

- **סנכרון עכשיו** — מעדכן את `journal-latest.json` *במקום*. קובץ אחד שמתעדכן, לא ערימה.
  רץ גם לבד, 20 שניות אחרי שינוי, אם יש הרשאה חיה.
- **גרסה מתוארכת** — קובץ נפרד עם חותמת זמן, שלא נדרס. לנקודות ציון.
- **שחזור** — מוריד קובץ וממזג לפי `id`. מוסיף רק מה שחסר, לא מוחק ולא משכפל.

יש גם ייצוא וייבוא JSON מקומי, בלי גוגל בכלל.

פורמט הקובץ:

```json
{
  "app": "tiny-journal",
  "schema": 1,
  "exportedAt": "2026-09-01T09:16:30.000Z",
  "count": 2,
  "entries": [
    { "id": "e...", "text": "...", "createdAt": "...", "createdAtMs": 0 }
  ]
}
```

## דברים ששווה לדעת

**מחיקת נתוני האתר מוחקת את היומן.** IndexedDB הוא אחסון דפדפן. "נקה נתוני גלישה"
מוחק הכל. זה בדיוק מה שהגיבוי קיים בשבילו — אל תדלג עליו.

**iOS מוחק אחסון של אתרים שלא נגעת בהם.** Safari מפנה אחסון אחרי כשבועיים
של אי-שימוש באתר. אפליקציה שהותקנה למסך הבית פטורה מזה, אבל אם אתה מתכוון
להשתמש דרך הדפדפן — סנכרן.

**המזהים הם client-generated.** `id` נוצר במכשיר, ולכן מיזוג בין שני מכשירים
עובד בלי התנגשויות. שני מכשירים שכותבים במקביל לאותו `journal-latest.json`
יידרסו הדדית — סנכרן, ואז שחזר בצד השני.

**אין הצפנה בצד לקוח.** הטקסט יושב כטקסט רגיל ב-IndexedDB ובדרייב. אם אתה רוצה
שגם גוגל לא יראה את התוכן, השלב הבא הוא WebCrypto עם מפתח שנגזר מסיסמה,
והצפנה לפני העלאה. שווה לדבר על זה אם זו הכוונה.
